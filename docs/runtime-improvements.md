# Runtime 可靠性改造

本次借鉴 kay-go 的任务状态、工具编排、历史记录与输出预算设计，保留 Python / Textual 实现。

## 执行与确认

- `RunState` 记录单次任务轮次；`SessionManager.turn_count` 保留会话累计轮次。权限确认不会重新获得一份轮次额度。
- `ToolRegistry.validate()` 在确认前校验参数；`ToolExecutor` 是自动执行与确认后执行共用的执行入口。
- “本次会话全部允许”保留当前待确认调用，执行当前操作后再处理后续队列。
- 停止时补齐未完成调用的取消结果，清空队列；每次请求通过 `build_api_messages()` 兜底规范化工具消息配对。
- TUI 负责展示和提交确认结果；运行时管理实际执行、任务计数、历史记录和取消收尾。

## 历史与上下文

- 原始历史 `_transcript` 独立追加；模型上下文 `messages` 可以被摘要替换。
- JSONL 保存游标跟踪原始历史；压缩后追加 `context` 检查点。恢复时应用最新检查点及后续事件。
- 保留旧 JSONL 的读取兼容。模型及轮次改变时追加 metadata。
- 序列化在写入前完成；写入失败回滚本次追加且不推进游标。进程崩溃留下的不完整末行可在下次保存时截除。
- 本地 JSONL 使用单写入者模型，不支持多个进程同时恢复并写入同一个会话。
- 会话 ID 使用 UUID；`/clear` 开始新历史，原文件仍可恢复。
- 压缩失败、返回空摘要或摘要未减少上下文时保留原始内容。工具 schema 与回复预留空间纳入请求预算；压缩后仍超预算则明确停止，避免继续发送必然过大的请求。
- 优先保留最近两次用户对话；无法按用户轮次压缩时，按完整助手/工具批次压缩，保留原始用户任务和最近两个批次。原始任务及最新结果自身过大时仍会触及预算。

## 工具边界与资源

- 内置文件工具限制到解析后的工作区路径；敏感检查同时覆盖符号链接目标。
- 本机 Shell 仅校验工作目录并做高危命令黑名单拦截，**不是操作系统沙箱**。经确认的命令仍拥有当前用户的文件与网络权限。要限制宿主机访问，需额外的容器或系统隔离后端。
- Unix Shell 使用独立进程组，取消/超时杀整组；Windows 使用 `taskkill /T /F`，其实际行为由 Windows CI 验证。
- stdout、stderr 分别最多捕获 1 MB，超过部分继续排空并丢弃；非零退出码作为失败返回。
- 普通工具输出超过 30000 字符时落盘至 `.tui-agent/results/`，模型收到预览及读取路径；落盘上限 2000000 UTF-8 字节，与文件读取上限一致；超限保留首尾并标明截断。历史工具结果进入请求时另有累计 100000 字符预算，优先保留最近结果。
- 搜索在独立进程运行：5 秒超时、最多检查 10000 个文件、最多 200 条匹配或约 30000 字符输出。跳过依赖、构建目录、符号链接目录、敏感文件和大于 2 MB 的文件；病态正则可被终止。
- `read_file` 在工作线程读取，最多 2 MB，展示最多 500 行和约 30000 字符。过长单行会明确截断，并返回从 0 开始的 `char_offset` 游标用于续读；游标不能与行范围混用。每次读取仍会加载上限内的整个文件。
- 默认注册表中的读/写/编辑工具共享有界已读缓存。同一内容版本的分页已读范围会合并，外部修改使旧范围失效。覆盖必须完整读取；编辑匹配必须在已读范围。内容摘要校验可发现保持 mtime 的外部修改。
- 编辑拒绝空字符串及多处匹配；写入使用同目录临时文件与原子替换，并保留现有文件权限。
- 文件确认显示可滚动 diff 预览；大 diff 会明确截断。已读检查仍会在实际执行时重新进行。
- Provider 流式响应在结束或取消时关闭；重试识别 OpenAI 和 Anthropic SDK 的连接/超时异常。

## 清理与配置一致性

- 删除未使用的上下文组装模块、队列兼容属性和无效统计字段，统一权限枚举，启用完整 Ruff F 规则清理未使用导入及局部变量。
- 配置默认值以 Pydantic 模型为准，`config/default.yaml` 仅作为用户配置示例。
- 模型/Provider 切换先构建候选客户端，成功后提交配置、运行时和会话模型；失败保留原状态，成功后异步关闭旧客户端。运行中或待确认时拒绝切换。
- 取消时移除工具运行卡片和思考状态。
- 持久化 fsync、写入和 diff 计算仍同步执行；有序后台持久化与只读工具并发可作为后续性能优化。

## UI 更新

状态栏优先显示当前状态；欢迎页支持窄窗口，确认预览适配短窗口。工具结果支持展开/收起，失败默认展开；操作方式见 [UI 使用说明](ui-guide.md)。

## SDK 流式退出兼容性

在 Python 3.12 + OpenAI 3.13.0 / httpx2 2.12.0 下，本机假 SSE 服务可复现立即退出时的 `PoolByteStream.__aiter__` / `generator didn't stop after athrow()`。同一探针在 OpenAI 2.44.0 / httpx 0.28.1 下通过。因此目前依赖限定 `openai>=2.44.0,<3`，属于兼容性规避，未修改第三方库或屏蔽 asyncio 异常；后续升级 3.x 必须先通过退出探针。

同时显式关闭嵌套的运行时生成器，正常响应读到协议结束；应用卸载时先取消并等待活动任务，再等待旧客户端清理并关闭当前客户端。

本机集成测试不使用真实密钥，仅监听回环地址：

```bash
STA_TEST_LOCAL_HTTP=1 python -m pytest tests/test_stream_shutdown.py -q
```

未设置该变量时跳过两个端口测试，CI 已启用。覆盖正常结束、中途关闭和异步生成器收尾；单元测试另验证任务清理先于客户端关闭。

## 任务检查点

`session/checkpoint.py` 独立维护任务状态和文件快照，区别于 JSONL 的压缩上下文 `context` 记录。AgentLoop 在任务/模型/工具边界同步历史与检查点，已完成、失败、等待确认、中断、轮次限制分别记录状态。

内置文件工具通过 `tracked_write` 先持久化修改前和预期内容，再原子替换目标文件。若进程停在中间，检查点允许核对实际文件仍是写前版本还是已成为预期版本；不推断 Shell 是否执行成功。`/resume` 复制已保存上下文到新会话，关闭待执行工具配对，重置授权和已读缓存，建立新的续接检查点。

`/undo` 预览绑定检查点内容指纹，确认后再次校验全部文件。撤销逐文件执行，磁盘失败保留可重试的 `undoing` 状态。文件冲突、符号链接、越界路径或 Git/STA 内部状态路径会拒绝覆盖。文件快照保留原始字节与权限位，不对需要恢复的内容做日志脱敏替换。

测试见 `tests/test_checkpoints.py`，覆盖持久化、恢复、新建/编辑撤销、外部冲突、写前日志、撤销中断重试和 TUI 确认。详细用法与限制见 [UI 使用说明](ui-guide.md#任务检查点恢复与撤销)。
